# Pisex / s2sdk — исходники для ПРОБНОЙ сборки, НЕ ДЛЯ СЕРВЕРА

Источник: диагностический архив пользователя `pisex-new-s2sdk-abi-evidence.zip`, коммит s2sdk `ab23a7e3dfa754ce822a70aa456f5be40eb3845e`.

Изменены `utils.h`, `utils.cpp`, `include/players.h` и тестовый `.github/workflows/test_pisex_new_s2sdk.yml`.

- Вместо отсутствующего `<iserver.h>` используются публичные `engine2/...` заголовки.
- Восстановлены `ProcessTick`, `ProcessStringCmd`, `IEntityResourceManifest::AddResource` по новым определениям SDK.
- Сигнатура `CServerSideClientBase::Connect` и шаблоны `CNetMessagePB<...>` согласованы с заголовками s2sdk.
- Тестовая сборка привязана к тому же коммиту SDK, что и присланная диагностика.
- Весь остальной код HUD оставлен без намеренного отключения.

**Это гипотеза на уровне исходников, а не собранный/проверенный плагин.** Полная компиляция и ABI запуска не проверены. Даже если сборка GitHub зелёная, НЕ устанавливайте результат на действующий сервер MyArena: сначала необходимы проверка символов, зависимостей, интерфейсов Metamod и испытания на отдельном тестовом сервере.

Чтобы опробовать: перенесите содержимое `cs2-menus-main` в корень репозитория, в том числе три исходника и `.github/workflows/test_pisex_new_s2sdk.yml`. Запускайте только `Test Pisex against newer Source 2 SDK (NOT FOR SERVER)`. Не запускайте основной старый workflow как тест нового SDK.

Если сборка красная, нужен журнал ПЕРВОЙ ошибки, не только его последние строки. Число ошибок не является достаточным критерием работоспособности.
