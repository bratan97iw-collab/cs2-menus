# Pisex Game Utils — API 18: состояние проекта

Этот архив содержит **весь проект**, включая оригинальные HUD-ресурсы и переработанные ранее исходники. Он **не содержит собранный или проверенный `utils.so`**.

## Почему пока не удаётся собрать

Последний GitHub Actions лог от 2026-11-04 показывает 8 ошибок C++:

- `CServerSideClientBase` (объявлен, но неполный класс): 4 ошибки, включая два указателя на методы и два вызова `GetPlayerSlot()`.
- `IEntityResourceManifest` (неполный интерфейс): 1 ошибка на `AddResource()`.
- `CNETMsg_Tick_t`, `CNETMsg_StringCmd_t`, `GameSessionConfiguration_t` (неполные типы): 3 ошибки в шаблонах KHook.

Текущие привязки SDK в `.github/workflows/build_pisex_khook_api18.yml` сами по себе **не дают полных определений** некоторых типов. Отсутствие определения класса нельзя безопасно устранить созданием фиктивного C++ класса или подстановкой произвольного номера виртуального метода: это создаст ABI-несовместимость и риск краша CS2.

## Что изменено сейчас

Workflow дополнен шагами `Capture complete relevant SDK headers and ABI evidence` и `Upload full SDK ABI evidence`. После запуска GitHub Actions (даже если сборка завершилась ошибкой) появится артефакт **`pisex-api18-full-abi-evidence`** с полными оригинальными заголовками, включающими указанные типы, и путями к ним. Это лучше усечённого `sdk-declarations.txt`, который уже исследовался. Исходники Pisex/HUD не отключены и не заменены чужими меню.

## Установка

1. Распаковать ZIP и загрузить его содержимое в репозиторий, сохраняя каталоги.
2. Actions → `Build Pisex Game Utils - full KHook API 18 attempt` → Run workflow.
3. Внизу Summary скачать артефакт `pisex-api18-full-abi-evidence` и передать для анализа.
4. **На MyArena пока ничего не устанавливать.** Успешной сборки и теста в игре ещё не было.

Важно: новый ZIP — диагностический полный проект для определения точной ABI, **не конечное исправление восьми ошибок**.
